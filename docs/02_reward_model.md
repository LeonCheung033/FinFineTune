# 奖励模型 (Reward Model) 微调指南

## 1. 核心背景

### 1.1 SFT 的局限性
在 SFT 阶段结束后，我们发现模型虽然具备了金融知识，但存在两个致命问题：
1. **答非所问 (Off-topic)**：用户问"风险提示"，模型却在描述"行情走势"。
2. **危险建议 (Safety)**：模型倾向于给出"赶紧抄底"、"全仓买入"等带有强烈主观倾向的建议，违反合规红线。

### 1.2 为什么需要奖励模型？
为了解决上述问题，我们引入 **GRPO (Grouped Relative Policy Optimization)** 强化学习。而 GRPO 的核心是 **奖励模型 (Reward Model)**。
- 奖励模型是 GRPO 的"指南针"。
- 通用奖励模型倾向于给"简单、流畅"的回答打高分。
- **金融专用奖励模型** 必须学会给"专业、合规、包含风险提示"的回答打高分。

---

## 2. 数据策略：5层质量分级

为了训练出能精准识别好坏的奖励模型，我们通过 **生成数据** 构建了一个精细的偏好数据集。

### 2.1 质量分级体系
我们不使用简单的"好/坏"二元分类，而是构建了 **5个质量等级**：

| 等级 | 分数 | 描述 | 特征 |
|------|------|------|------|
| **Low** | 1分 | 低质量 | 逻辑混乱，信息严重错误 |
| **Medium-Low** | 2分 | 中低质量 | 基本正确，但分析浅尝辄止，无风险提示 |
| **Medium** | 3分 | 中等质量 | 正确且流畅，但不够全面 |
| **Medium-High** | 4分 | 中高质量 | 专业且全面，有一定风险意识 |
| **High** | 5分 | 高质量 | **专业、全面、深入，且包含明确的风险提示和免责声明** |

### 2.2 组合对生成 (Combinatorics)
对于同一个问题，我们生成上述 5 个等级的答案。这使得我们可以从每个问题生成 $C_5^2 = 10$ 对偏好数据（例如：等级5 > 等级2，等级4 > 等级3）。
相比传统的二元标注（1个问题产生1对），数据利用率提高了 **10倍**。

### 2.3 数据混合策略
为了保持与 SFT 阶段的连续性，同时引入多样性，我们采用了混合数据源：
- **30% 复用 SFT 数据**：从已有高质量对话中提取问题，确保模型不忘"老本行"。
- **70% 新生成问题**：基于金融新闻生成全新问题，扩展模型的知识边界。

## 3. 技术架构

### 3.1 训练流程
1. **问题生成 (Question Gen)**：使用 LLM 从金融文章中提取问题。
2. **答案生成 (Answer Gen)**：对每个问题，使用 LLM 并发生成 5 个不同质量等级的答案。
3. **数据构建 (Pair Construction)**：将答案两两组合，形成 `(prompt, chosen, rejected)` 三元组。
4. **模型训练 (Training)**：使用 Pairwise Loss 训练 Reward Model。

### 3.2 目录结构
```
src/reward_model/
├── data_generation/    # 数据生成模块
│   ├── question_generator.py
│   ├── answer_generator.py (核心：生成5级答案)
│   └── data_splitter.py
├── train_reward_model.py # 训练脚本
└── inference/          # 推理服务
```

## 4. 训练配置

**基础模型**: Skywork-Reward-Llama-3.1-8B (在该领域表现优秀的开源奖励模型基座)

由于全参数微调 8B 模型对显存要求较高，且奖励模型极易过拟合，我们采用了 **Freeze Tuning (部分参数冻结)** 策略。

### 4.1 Freeze Tuning 策略
代码实现中 (`train_reward_model.py`) 默认采用以下配置：
- **冻结**: 主干网络 (Backbone) 的前 28 层。
- **训练**: 
  - 最后 **4** 层 Transformer Layer。
  - **Score Head** (分类头)。
- **优势**: 相比 LoRA，Freeze Tuning 在奖励模型任务上往往能保留更多的预训练知识，同时参数量和显存占用也相对可控。

### 4.2 超参数配置
根据 `configs/training/config.json`，实际使用的超参数如下：

- **Learning Rate**: `5e-5` (Freeze Tuning 需要比全量微调稍大的学习率)
- **Batch Size**: `32` (Per Device 2 * Accumulation 4 * 4 GPUs)
- **Max Length**: `512` (奖励模型主要关注回答的逻辑和风格，512 长度通常足够)
- **Epochs**: `2` (避免过拟合)
- **Precision**: `BF16` (BFloat16)

## 5. 常见问题

**Q: 为什么要生成"差"的答案？**
A: 奖励模型不仅要认识"什么是好"，更要深刻理解"什么是差"。通过让模型看到"缺乏风险提示"的回答被标记为 rejected，它才能学会风险提示的重要性。

**Q: 为什么不直接用 GPT-4 打分？**
A: GPT-4 的打分通常是绝对分数（Pointwise），且成本极高。我们使用本地模型训练完成后，可以低成本、高并发地支持 GRPO 的大规模采样训练。

**Q: 训练完怎么用？**
A: 训练好的奖励模型将作为一个独立的微服务（Ray Service）运行，为后续的 GRPO 训练提供实时打分服务。详情见 [GRPO 训练指南](03_grpo_training.md)。
